# Roblox Dev (scripting)

## Why scripts matter
Everything that *happens* in a Roblox game is a script: movement rules, combat, money, pets, shops, saving, UI, effects. Parts and models are just the stage. Scripts decide:
- **Fun:** the core loop, rewards, feel (tweens, VFX, sounds are all scripted).
- **Stability:** no errors, no lag, no broken states when players join/leave or servers shut down.
- **Fairness:** exploiters run their own code on their client — only server scripts stop them from giving themselves money or killing everyone.
- **Trust & money:** lost data or failed purchases = angry players, refunds and bad ratings. Saving and purchases must be bulletproof.

## 1. Structure (where code lives)
| Place | Runs on | Put here |
|---|---|---|
| `ServerScriptService` | server | game systems: data, money, damage, drops, purchases, round logic |
| `ReplicatedStorage` | both | shared ModuleScripts (config, utility, VFX/Motion), RemoteEvents in a `Remotes` folder |
| `ServerStorage` | server only | items/maps to clone, secret config |
| `StarterPlayerScripts` | each client | input, camera, UI controllers, cosmetic effects/motion |
| `StarterGui` | each client | ScreenGuis (+ their LocalScripts) |
- One `Main` Script per side that `require`s ModuleScript systems (each system = one module with `Init/Start`), not dozens of loose scripts.
- Config (prices, odds, cooldowns) in one shared module so balancing is one file.
- Cosmetic stuff (spin, bob, VFX, UI tweens) on the **client**; anything that matters on the **server**.
- Use `--!strict` / typed Luau in modules where practical; `task.spawn/defer/wait` (not `spawn/wait`); disconnect connections; `pcall` every DataStore / Marketplace / HTTP / Badge call.

## 2. Security — never trust the client
Exploiters can: fire any RemoteEvent/ProximityPrompt/ClickDetector from anywhere at any time, ignore client-side `Enabled`/`MaxActivationDistance`, send wrong types, huge strings, fake "instance" tables, NaN/inf, and take network ownership of unanchored parts.
**Server rules:**
- Server owns money, items, health, damage, cooldowns, ammo, team, alive state. Client only *asks*.
- Validate every remote: types and table shape, string/collection size caps, Instance class + `IsDescendantOf(expected folder)`, `math.isfinite` (NaN passes range checks silently — check `x ~= x` on Vector3 parts), value ranges, ownership/permissions (owns item, enough coins, alive), **distance** (server-side, with latency slack), line-of-sight for shots.
- Never let the client pick a path/instance for the server to modify/delete, or a module to `require`/asset to load.
- **Rate-limit** on the server (token bucket per player per remote; clear on `PlayerRemoving`), especially currency grants, teleports, DataStore/Badge calls.
- ProximityPrompt: only `Triggered` gets a server distance check; ClickDetector: none — validate yourself.
- Validate before `FireAllClients` — the server is a gatekeeper, not a relay.
- Critical physics: anchor parts or manage network ownership.
- **Free Creator Store models can carry backdoors** (a "low poly palm" hid Scripts under `Humanoid > HumanoidDescription`). After every insert, list `LuaSourceContainer` descendants; decor with scripts → delete the model. MCP `insert_asset` returning `sandboxed:true` = it found scripts. Keyword-stuffed names are usually reuploads; plain names + older IDs are safer. Full insert → scan → clean → restyle flow and scanner: `roblox-store-models`.
- **Gates the client can't fake:** the client owns its Humanoid (JumpPower, flying), so gate jump/area unlocks on server data AND a server-sampled HRP position in that area; put the check in the shared station-distance helper so every station gets it.
- **Item machines (fuse, craft, upgrade):** rules in a pure shared module (client preview = server check); preview returns a one-use token bound to (player, inputs, choice, 120 s); commit re-validates, mutates in one non-yielding block, caches the result per token (repeat = same result). Template `ConfirmToken`.
- A RemoteEvent can later become a RemoteFunction without breaking clients if all calls go through one request helper that checks `ClassName`.
- **(promoted 2026-10-28) Item-changing remotes:** exactly-once via a client nonce — server reserves it "pending" before any yield, caches the result (small LRU), a repeat returns the cache (re-fire the visual); test same nonce twice = one charge. New params: optional trailing args; refusals as `{ Ok = false, Code }` so the UI can say why (busy / tokens / storage). All three in `RemoteGuard` v2.
- **(promoted 2026-10-28) Movement cheats on client-owned characters:** a height cap (feet above last ground > one launch at full airtime + every allowed air jump + 8 studs) caught 3/3 infinite-jump runs with 0 false flags; a 10 Hz "vy jumped" counter missed half (replicated vy is smoothed). Measured jump chains peak ~4% (~4 studs) over the maths — measure real jumps before sizing a cap or a gap meant to block a jump (2026-11-03). Fall recovery = last spot stood on (ray down, |vy| < 4 for 0.25 s).
- **(promoted 2026-10-28) Busy locks + replays:** skip/leave shortens the lock to a floor, never clears it (else skipping = farm-speed exploit); rewards granted before a replay get their toast at the replay's End (timeout fallback).
- **(promoted 2026-10-28) Server auto loops** (auto hatch/open): one run per player, a per-player `lastRollAt` that survives stop/start (else stop/start spam beats the cadence), blockers polled between windows, one batched result event per roll; when a batch is refused mid-roll, re-derive the reason (storage/currency) instead of "error".
- **(2026-11-03) Remotes + boot:** remote names are global, one name = one owner — grep every service on disk AND in Studio before adding one (a duplicate throws in `Init` and stops every later service; check the boot's "services started" print in Play). A net module with an EVENTS allow-list needs each new name, or `Fire` only warns. Create remotes at startup: a lazily made RemoteEvent's first `FireClient` drains to whichever listener connects first. `Start()` also loops `Players:GetPlayers()` (the Studio player joins before Start).
- **(2026-11-03) Stations:** tags also live on ServerStorage backup copies → filter `IsDescendantOf(workspace)` in every "apply to tagged" / nearest lookup. A range helper must never skip its check when nothing is tagged (a Studio-only fallback hid a live server that refused every open) → keep a test that the tagged stations exist in Workspace. Busy lock that scales with batch size = "busy-until" (`last = now + LockSeconds(n)`); batches feed/pay once in the caller after caching the nonce (inner call returns early on `opts.Batch`).
- **(2026-11-03) Full inventory:** an auto-convert of plain rolls must still charge (a free refusal = free reroll that only pays for rares); if nothing can be deleted, refuse BEFORE the roll.
- **(2026-11-03) Dev → live:** before the first publish grep every client script for `if not RunService:IsStudio() then return end`, move real requests off the DevCommand remote onto a production remote with full server checks, sweep Workspace for untagged preview folders. Remotes that edit a structured record (settings/filters): one call per change (group, key, value) with the rules in a shared module the client panel also requires — never a whole-table upload (RemoteGuard has no table type by design). Auto/bot loops: every reward path (bot fights, auto runs) goes through the same reward limiter.
- **(2026-11-05) Wallet + perk gates:** premium-currency reason allow-lists must Studio-gate `"dev"`/`"test"` reasons (`RunService:IsStudio()`) or any server path with such a reason mints premium currency live. Turning a paid perk free: move its tuning out of `Config.GamePasses`, drop the server gate and the `Owns*` mirror (clear the old attribute on join), keep the remote's rate limit, let the real service path judge affordability. Whitelists like `Sources[src] == true` silently skip every new source → `~= false` (default on, explicit opt-outs) and grep every grant path before calling a rule "everywhere".
Template: `roblox-templates/templates/RemoteGuard.lua` (validated + rate-limited remotes; v2: optional args, refusal codes, exactly-once nonces).

## 3. Player data (saving)
- **Use ProfileStore** (loleris; successor to ProfileService): session locking + autosave + reconcile in one ModuleScript. Install from its DevForum/GitHub page. Session locking stops two servers editing the same player (= duplication exploits).
- If hand-rolling: `UpdateAsync` (not `SetAsync`) with a session lock field, autosave every 60–120 s, save on `PlayerRemoving`, `game:BindToClose` to save everyone (Studio: skip/short), retry with backoff, **never** overwrite real data with a default template after failed loads (kick with "data failed to load, rejoin" instead).
- Data shape: one table per player with a `Version` number; migrate old versions on load; no Instances, no NaN/nil keys; sanitize strings (`utf8.len`, length caps).
- Limits (per server per minute): Get/Set/Remove **60 + players×40**, List 5 + players×2, ordered write 30 + players×5. Per key: 4 MB value max, 4 MB/min writes, 25 MB/min reads; key name ≤ 50 chars. Queues hold 30 requests then drop (errors 301–306). Experience-wide: reads 300 + CCU×40, writes 300 + CCU×20.
- Trades/multi-step changes: validate everything first, commit together, revert all on any failure.

- **Patterns that worked (projects, promoted 2026-10-24):**
  - New per-item roll (aura, shiny): one optional field + a pure config module (`{Chance, RareBoost}` per source + an `Odds()` the UI reuses); roll in the ONE item-creation service, before any auto-delete decision; carry through fusion as "rarest input"; migration only fixes bad types and keeps unknown ids. Store rolled stats as 0–1 quality so rebalancing rescales owned items.
  - Trading needs globally unique item ids (per-player counters collide): upgrade to a GUID when first offered and repoint team/equip refs.
  - Two-player trade without a central store: save a PendingTrades record (gives + exact copies of gets) to both → apply both in one non-yielding block → save both; on load, read the partner's record and roll forward/undo with the same apply function. Safe for one server crash, not every rejoin race — keep trading Studio-only until a 2-client + published crash test passes.
  - Big per-item data blows up client sync: pack items with a codec (only fields the client can't derive from config), round-trip test, then move to delta sync.
  - Tests: assert `Version >= n` for old migrations and keep ONE "current version" check. Migration tests with injected profiles touch only the in-memory store (with Studio API access on they'd overwrite the dev's real save).
  - A Config folder whose init requires every child: helpers (odds, boosts) go in their own child module — functions added to a data table break `pairs()` loops. Don't name a service's own function `Start` if the boot loader calls `svc.Start()`.
  - **(promoted 2026-10-25)** Retiring a mechanic: migrate the old field into the new one on the SAME item (keep ids), also run it in the every-load repair so stale copies (pending-trade records) convert; rebuild derived books (collections) with an add-only backfill and test idempotency by migrating twice.
  - Equip-one-of-many (body/skin per pet): the item field (`pet.Body = uid`) is the only truth; DERIVE "equipped on" in the sync codec so trade/delete/rekey need no bookkeeping (strip it from traded copies).
  - Passive income ticking every second: update the currency attribute live (no sync) and MarkDirty at most every ~10 s from income alone — never a full snapshot per tick.
  - **(promoted 2026-10-28)** Regrouping items (new chest/slot families) without a migration: derive the group from config on read (def override → category map → `Legacy`), keep old ids. Retiring shop ids: two resolvers — `Resolve` (follows alias/redirect chains, hop cap) and `Base` (the row whose odds old UI/tests read). Pre-rolled cosmetics: one `RollFor(kind)` returning skin/shiny/provenance + one `Disclosure(kind)` the UI reuses; pass provenance through Force/NoRolls adds.
  - **(promoted 2026-10-28)** Keep a test that walks every enabled drop pool and resolves each entry to a real model; pull placeholders out of the pool, not out of config, so saved items still load.
  - **(2026-11-03) Retire, never delete:** flags on rows (`Enabled=false, Hidden=true, Retired="<why>"`, shop `Availability="Disabled"`), keep item rows so owned copies and redirects resolve. A new design for a placeholder id updates the existing record in place. Registries: explicit records + a loud `Validate()`, no "auto-register by id prefix" (it hid gaps). "Done" for new content = config row + pool entry + asset copy in Studio; audit Studio vs repo after every content swap. Removing a meta entry turns test lookups nil silently → grep tests for the id; tests picking "any disabled row" must pick one with `Resolve(id) == id`.
  - **(2026-11-03) Renames:** a renamed currency moves each legacy key's exact value into the new key, parks old keys in a `Legacy…` audit table, never overwrites an existing new value. Rename retired ids in the every-load repair AND after trade reconcile (pending-trade copies come back after migrations). Every-load clean (finite, whole, ≥ 0) clamps at a hard sanity cap, not the soft gameplay cap (paid grants may pass it). A setting carried over to a new system (auto-delete) must be opt-in, or players silently lose rolls.
  - **(2026-11-03) Rolls:** ultra-rare tiers (1 in 500k+) don't go in a float weight table — give each a fixed integer share of one denominator, draw one `Random:NextInteger(0, D-1)`, rarest block first, then the normal pool with integer weights; cap luck per tier and test exact block edges with forced draws. A boost = weight × mult only when a boost table is passed (no boost → byte-identical RNG path, old tests/saves don't move). Rarity names vary (Mythic/Mythical, Secret I–IV): normalise or prefix-match.
  - **(2026-11-03) Derived progression** (ranks, quests): a `Dirty` signal from the one `MarkDirty`, per-player 0.5 s debounce, MarkDirty again only on a real change (no loops); store best progress so spending/trading never revokes credit.
  - **(2026-11-03) Cross-server** (queues, markets, arenas): the DataStore record is the truth, MemoryStore only an index; a read reports "read failed" apart from "not found"; buys = pending debit + single-use id. Leave cancels the entry and its match, never match two players from one server, every arrival needs a way home. Handle only teleport failures you started, cap retries. Copy venues from a ServerStorage template. MemoryStore/Teleport behind adapters with mocks.
  - **(2026-11-03) Moving buildings:** lookups by tag + attribute survive a whole-model `PivotTo`; full paths break (tests, build scripts, hide lists) → keep old parent folders. A retired build script that "clears + rebuilds" undoes later moves → add a refuse guard in the same change.
  - **(2026-11-05) Migrations:** when a field changes meaning, every OLD migration step that reads it must skip data already in the new shape (guard on a `NewShape` flag) or re-runs wipe balances; regex renames hit config paths and fixtures too (lookbehind or file allow-list, re-run every suite). Item-strip migrations = a pure Lib module (`Strip(data, Config)`, nil-safe, stamps a version) called from load repair AND after trade reconcile, so Edit tests drive it on a fake save. A migration gate that kicks old saves makes dev load helpers return "gated".
  - **(2026-11-05) Versioned grants:** one-time grants on load tag each row `Since = N` and grant only rows newer than `data.<Set>Version`, skipping ids already owned (never "regrant everything missing" — it returns items players deleted). Rank/unlock gates read the highest rank EVER reached, not the current one (rebirth resets it). Item copies under a new id carry `LookAs = <source id>` mapped once where the build starts, so visual readers keyed by id keep working. Retiring a slot: drop it from the order list but keep its socket def + category map (other systems read them directly).
  - **(2026-11-05) Global serials / limited editions:** one DataStore key per edition, changed only with `UpdateAsync`; the transform is pure and the caller keeps only the LAST run's value; store `Ops[opId] = serial` so a replayed op returns its old serial with no write; cap = `min(stored Supply, config)`. Small per-player prefs (pinned HUD apps) fit in the existing Settings blob (no schema bump): validate with a RemoteGuard spec + a shared pure `Clean*` that refuses the WHOLE request on any drop and re-sends the saved attribute so the client snaps back; client debounces sends ~0.6 s and re-reads the attribute ~2.5 s later.

## 4. Purchases
- **Developer products:** grant only in the receipt handler — `MarketplaceService:BindReceiptHandler` (newer) or `ProcessReceipt`. Never on `PromptProductPurchaseFinished` (doesn't confirm a sale).
- Handler must be **idempotent**: record `PurchaseId` in the player's saved data (UpdateAsync/ProfileStore) before/with the grant; if already recorded, just return granted. Return `NotProcessedYet` if the player isn't in this server or saving failed — Roblox retries later. Only one handler for the whole game.
- **Game passes:** `UserOwnsGamePassAsync(userId, passId)` (pass ID, not asset ID) in `pcall` on join; listen to `PromptGamePassPurchaseFinished` to grant instantly. Results are cached; purchases made outside the game can take minutes to show.
- **(2026-11-03) From projects:**
  - New paid systems plug into the ONE receipt handler (an `ItemForProduct(id)` fallback + one canGrant/grant branch each). Grants are all-or-nothing and paid grants skip soft caps (a partial grant retries forever); a grant into a full wallet is logged and counted as granted. No ProductId yet = Placeholder.
  - Currency shop items that grant a roll/item: check delivery (space, item exists) BEFORE charging, grant in `pcall` + refund on error, return the result and still fire the normal reveal event.
  - Server-wide boosts: pass a `paid` flag to every roll helper AND to the odds the UI shows, so boosts never touch Robux opens and disclosed odds stay true; keep special luck as its own parameter. Paid timed boosts survive shutdown: record use slices, fire a Closing signal in `BindToClose` before final saves, bank unused time into the profile (or a side-store refund record for players who left, paid once on join, paid ids kept).
  - Policy-gated paid random items: a receipt can arrive while the policy reads restricted/unknown — never `NotProcessedYet` forever. Grant normally if the prompt was recorded while confirmed allowed (7-day window); else grant a fixed non-random credit, save, `PurchaseGranted`.
  - Disclosed odds with bonus rolls: show the bonus lines and compute headlines from the true total. Odds text: round half up with an epsilon (`math.floor(x*100 + 0.5 + 1e-7)/100`; `%.2f` shows 2.165 as 2.16); tests check the raw percentage, not the rounded "1 in N".
  - Robux ledger: count `receipt.CurrencySpent` in the same no-yield block that records PurchaseId; passes once per id via `GetProductInfo` in `task.spawn`.
  - Rules of Conduct ban simulated gambling: never stake currency, items or pets on a match (even free-earned ones); keep a test that greps scripts for wager/stake remotes (`%f[%w]` frontier patterns).
  - (2026-11-05) A "Pick one" / direct buy offered to `ArePaidRandomItemsRestricted` players becomes a paid random item again if it rolls a random Shiny/overlay: put that roll behind a config flag (reusing the random open's exact roll function), ship it OFF and flag it for lyopz.
Template: `roblox-templates/templates/PurchaseHandler.server.lua`.

## 5. Performance
- No `while true do` busy loops without waits; prefer events (`Changed`, `Touched` with debounce, `Heartbeat` only when needed).
- Throttle UI updates; pool objects (projectiles, damage numbers) instead of creating/destroying every frame.
- Server does logic; clients do visuals. Keep remote traffic small (send IDs/numbers, not big tables), batch where possible.
- Use `StreamingEnabled` for big maps; check the MicroProfiler / Developer Console (F9) for spikes.
- **(promoted 2026-10-28)** Atomic models under StreamingEnabled aren't on the client when a scene starts: server `RequestStreamAroundAsync` before moving the player, client waits for the parts it needs, and the view claims its stage BEFORE yielding (no fallback double-build). Place stands by raycast onto the ground, not fixed coordinates.
- **(2026-11-03) StreamingEnabled, more:** models replicate in pieces → client rig/FX scripts rescan on DescendantAdded/Removing (debounce ~0.3 s, ignore their own pieces or they re-attach forever) and keep rest values in attributes (a rescan must not capture a pulsed value); `ModelStreamingMode = Atomic` where a script needs every part. A NaN CFrame on any part streams an Atomic model out and back → never `math.huge` "long ago" timers, guard `x ~= x`. `GetTagged` misses instances not yet in the DataModel. Teleports move the player's anchored pet models on the SERVER too. A Workspace Script with client RunContext doesn't run with streaming on → LocalScript in PlayerGui. Far test labs arrive with 0 descendants (clones build empty at the origin, budgets read 0) → from the Server DM anchor + PivotTo the character beside it (or `RequestStreamAroundAsync`), wait for its BaseParts, then clone; `Persistent` mode for that session only; retag client lab copies so live controllers ignore them.

## 6. Testing
- Studio: Play (solo), and **Test → Local Server with 2–3 players** to catch replication and join/leave bugs.
- Watch Output (errors/warnings), F9 console on live servers, Error Report/analytics on the Creator Dashboard.
- Test data: join, earn, leave, rejoin; shut down a server mid-session; buy a product in Studio test mode; try firing remotes with bad values (it should be ignored, not crash).
- Before publishing: run `roblox-reviewer`.
- **(2026-11-03) Test hooks:** long yielding runners (match replays, lineup windows) get an `Instant` option; locks get a `_ClearLock` dev hook; data services take `_InjectForTest` with a fake player (`UserId < 0`, `Parent = Players` or "player left" loops stop, `SetAttribute` stub). Dev give tools reject unknown ids loudly. Spy wrappers: take the first call after a mark and compare with `JSONEncode`, not identity. Chained timed states carry the overshoot (`t -= duration`) and log the change before entry cues; staggers schedule from one start time (`os.clock() - t0 >= target`), not chained waits. Economy sims subtract purchases; rerun the old economy through the same sim before comparing.
- **(2026-11-03) Fixtures:** tests that find world instances by tag override the lookup to their temp instances (restore after); read expected values from Config, not hard-coded content; clear service locks between phases; try new content on lab copies via Studio-only attributes (untag the live one, restore). Path checks sampled every 2 studs miss box corners → box-only half-step tests + a continuous 0.2 s audit of the replicated mover.
- **(2026-11-03) Shelve, don't delete, a feature:** move its models to one ServerStorage backup folder (`OriginalParent` attribute per child), strip CollectionService tags into a `WasTagged` attribute (else `GetTagged` returns both copies), gate every script on one Config flag checked `== true`, keep its remote registered so it answers "disabled" instead of hanging. `PivotTo` only moves Models (lift a lone BasePart via CFrame).
- **(2026-11-05) Tests:** Edit-mode `require` keeps serving the PRE-sync module even in a fresh `execute_luau` → `require(module:Clone())` or clone the whole Shared folder and require from the clone (pass the clone into suites); Edit service tests clone the service and `gsub` its `ReplicatedStorage.Shared`/`script.Parent...` requires to the clone/stubs (mock NetService needs Invoke/On/Notify). Prove "same odds as X" with seeded equality (`Grant(Random.new(seed)) == XRoll(Random.new(seed))` for 1..N) + a 5-sigma rate check. Tests that toggle shared config snapshot and restore it. Staggered spawns (cue first, then mob) need a per-zone `Pending` count or a KO during the delay overfills the zone. Raycast-check map markers (spawn, eyes, fog) from the apron — a SpawnPoint inside the rock mesh hid the whole cue.

## 7. Studio MCP & engine gotchas (from projects)
- `start_stop_play` spawns like "Play Here" (where the edit camera looks): aim the camera at the spawn first. Keep SpawnLocations flat and invisible on top of a decorative part (a sideways-rotated one spawns players off to the side).
- `screen_capture` can hang > 120 s on models with 1000+ parts (too heavy for phones anyway); captures right after terrain edits can be stale. Edit-mode captures DO show particles and beams (re-checked 2026-10-27) — set the camera in the same call right before capturing.
- `Lighting.Technology` errors in `execute_luau` even when read: `pcall` it, set Future by hand.
- EditableMesh in play needs Game Settings > Security > allow Mesh/Image APIs ("EditableMesh is not accessible"). Server/edit can create one when clients can't, so pick fallbacks on the client. Max extent 2048 studs; the MeshPart keeps its creation size (add tiny hidden triangles at ±max height for flat meshes). Client `WriteVoxels` didn't apply in MCP play tests.
- **MCP `execute_luau` runs in its own VM:** `_G` from game scripts is invisible; threads it spawns KEEP running after the call returns (a Heartbeat loop runs ~60 fps — stop it via a `_G` flag and check it stopped); `require` gives a fresh module copy with empty live tables (drive live tests through the real remotes, read replicated attributes) (Edit mode also caches require — clone the ModuleScript to test edits). Drive dev tools through a Studio-only DevCommand remote / Debug BindableFunction from the Client DM; test long animations through the real remote; LocalScripts gated on a LocalPlayer attribute keep running.
- Can't set from MCP: `Lighting.Technology`, Workspace streaming properties (StreamingTargetRadius etc.) → set by hand, say so in the report.
- Movement tests: `Humanoid.Jump` is overwritten each frame → `ChangeState(Jumping)` + drive HRP velocity on Heartbeat. Prompts: `prompt:InputHoldBegin()/InputHoldEnd()` on the Client after `character_navigation`. Under Device Simulator `user_mouse_input` misses GUI buttons → use shortcuts or toggle Visible. Teleport tests must stay inside any map bounds check.
- Device simulator: service is `StudioDeviceSimulatorService`; named presets can break → `CreateDeviceAsync({Name, Width=800, Height=360, PixelDensity=96})` + `SetDeviceAsync` from the Client DM (SetOrientationAsync needs a mobile device first).
- `screen_capture`: can hang or time out for a whole session (then verify by AbsolutePosition/Size per device and report shots as pending); lands 1–3 s after return (add a "hold" switch for timed effects); BillboardGuis never draw in captures (verify by instance + `WorldToViewportPoint`); far SurfaceGui text can be blank first time.
- Spatial queries (`GetPartBoundsInRadius` etc.) skip CanQuery=false decor — to find a stray bright part, loop the model's descendants by distance. Temporary tagged parts made during Play are a clean way to test unplaced stations.
- StreamingEnabled: a tagged Model can arrive before its children — client decorators retry for a few seconds.
- Script sync: serve files with `python -m http.server --bind 127.0.0.1` (one port per agent; two on one port fail silently), HttpGet with HttpEnabled on only for the fetch, normalize CRLF, `loadstring` compile-check before setting `.Source`, sync whole files (anchor patches break on CRLF). Big UI builders hit the 200-locals limit → wrap sections in `do ... end`. Map builds: one file per building + shared lib, each chunk clears + rebuilds itself.
- Shared Studio: save the place to file/Roblox before building (unsaved places can close); check `list_roblox_studios` before long jobs; lock finished map parts (`Locked=true`). Many agents: Play lock file (`_studio_play.lock` "<role> <unix-time>", ≤ 3 min, re-read before each capture, same clock that wrote it), sync only an allow-list of your files after diffing Studio vs disk.
- Meshes (2026-11-07): Studio MCP can now upload models/images itself — enable **MCP Permissions → Publish & manage assets** (+ Upload folders) per game; `open_cloud_invoke` + Studio's `rbx-import-asset` skill export GLB/FBX → upload → insert → fix scale/rotation/textures (uploads are permanent and moderated; confirm before uploading; delete only in Creator Dashboard).
